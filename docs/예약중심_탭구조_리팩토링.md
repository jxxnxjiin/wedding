# 예약 중심 탭 구조 리팩토링 계획

## 목적

Easy Wedding MVP를 예약 중심 서비스로 확장하기 위해 하단 탭과 화면 책임을 재정의한다.  
현재는 `찾기`, `예약`, `좋아요`, `비교`, `AI`, `프로필`, `로드맵` 기능이 어느 정도 구현되어 있으나, 향후 웨딩홀 외에도 스튜디오·드레스·메이크업·스냅 예약이 추가되면 탐색/예약/저장 흐름이 쉽게 비대해질 수 있다.

따라서 예약은 하단 주요 탭으로 유지하고, 탐색은 업체 발견과 비교에 집중시키며, 예산은 별도 탭으로 승격한다.

## 현재 구현 요약

### 홈

- 예식 D-day와 예식 예정일 표시
- 신랑/신부 프로필 진입
- 오늘의 할 일 카드
- AI 질문 진입 카드
- 이번 주 체크리스트
- 부가 서비스 목록

### 로드맵

- 전체 준비 단계 가로 스텝퍼
- phase별 체크리스트
- 체크리스트 완료/해제
- 체크리스트 제목과 메모 수정
- 체크리스트 category, dueDate, owner 표시

### 찾기

- 웨딩홀 추천 목록
- 필터 칩
- 업체 좋아요 저장
- 업체 상세 진입
- 저장한 후보 비교 진입

### 예약

- 예약 확정 업체 목록
- 대기중 업체 목록
- 방문 질문지 진입
- 좋아요 누른 업체 목록 진입

### AI 상담

- 추천 질문
- 채팅 입력
- 데모 고정 응답
- 새로고침

### 프로필

- 홈 프로필 버튼에서 진입
- 신랑/신부 프로필
- 온보딩에서 선택한 예식 조건 요약

### 예산

- 독립 화면은 아직 없음
- 온보딩 예산 범위, 프로필 요약, 체크리스트 category로만 일부 존재

## 목표 하단 탭

하단 탭은 다음 5개로 재구성한다.

1. `홈`
2. `로드맵`
3. `업체`
4. `예약`
5. `예산`

`AI 상담`은 하단 탭에서 제외하고, 홈/업체 상세/비교/예약/예산 화면에서 열 수 있는 공통 도우미 또는 sheet로 유지한다.  
`프로필`은 하단 탭이 아니라 현재처럼 홈 헤더의 커플 프로필 버튼에서 진입한다.

## 목표 화면 책임

### 홈

홈은 전체 진행 요약과 오늘/이번 주 액션에 집중한다.

- D-day
- 현재 phase 요약
- 오늘의 핵심 액션
- 이번 주 체크리스트
- 일주일 이내 예약 일정 요약
- 부가 서비스 미니앱 런처
- AI 빠른 질문 진입
- 프로필 진입

홈에 직접 들어가도 되는 미니앱:

- 내 체형에 맞는 드레스 추천받기
- 모바일 청첩장 만들기
- 웨딩홀 투어 지도로 확인하기
- 예산 초과 위험 확인하기
- 방문 질문지 만들기

### 로드맵

로드맵은 준비 일정과 체크리스트의 원천 관리 화면이다.

- phase별 전체 일정
- phase별 체크리스트
- 체크리스트 수정
- category, dueDate, linkedReservation, linkedVendor 확인
- 예약/업체/예산과 연결되는 task 표시

로드맵에서는 “무엇을 해야 하는가”를 관리하고, 예약 탭에서는 “예약 상태가 어떻게 진행 중인가”를 관리한다.

### 업체

기존 `찾기` 탭을 `업체` 탭으로 확장한다.

내부 구성:

- `추천`
  - 업체 추천 목록
  - category 필터: 웨딩홀, 스튜디오, 드레스, 메이크업, 스냅
  - 조건 필터
- `저장`
  - 좋아요/저장한 업체
  - 저장된 비교 리포트
- `비교`
  - 저장한 후보 비교
  - 비교 리포트 저장
  - 물어보면 좋은 질문 목록

초기 MVP에서는 웨딩홀 중심으로 유지하되, 구조는 모든 vendor category를 받을 수 있게 둔다.

### 예약

예약은 서비스의 핵심 탭으로 유지한다.

내부 구성:

- `전체`
- `확정`
- `대기`
- `요청`
- `방문 기록`

필터:

- 웨딩홀
- 스튜디오
- 드레스
- 메이크업
- 스냅

예약 카드에 포함할 정보:

- 업체명
- vendor category
- 예약 상태
- 희망/확정 일정
- 다음 액션
- 방문 질문지
- 캘린더 보기
- 관련 체크리스트 연결
- 관련 예산/견적 연결

예약은 탐색 탭 내부에 합치지 않는다.  
예약이 핵심 서비스이므로 별도 탭으로 남겨 “진행 관리”의 중심축을 담당하게 한다.

### 예산

예산은 새 하단 탭으로 추가한다.

초기 구성:

- 전체 예산
- 사용 금액
- 남은 예산
- category별 배분
- category별 사용/배정 진행률
- AI 예산 코치 진입

확장 구성:

- 예약 견적과 연결
- 계약금/잔금 관리
- 비교 리포트의 예상 비용과 연결
- 체크리스트의 budget category task와 연결

초기 예산 category 예시:

- 웨딩홀 · 식대
- 스드메
- 혼수 · 신혼집
- 예물 · 예단
- 기타 · 예비비

## 데이터 구조 변경 방향

### Screen

현재 screen:

- `find`
- `reservations`
- `saved-venues`
- `ai`
- `my`

목표 screen:

- `vendors`
- `vendor-detail`
- `vendor-compare`
- `reserve`
- `reservation-done`
- `reservations`
- `visit`
- `roadmap`
- `budget`
- `profile`
- `home`
- `onboard`

`ai`는 독립 screen을 유지할 수도 있으나, 1차 리팩토링에서는 하단 탭에서 제외하고 sheet 접근을 기본으로 둔다.

### Vendor

이미 다음 category가 정의되어 있으므로 유지한다.

- `wedding_hall`
- `studio`
- `dress`
- `makeup`
- `snap`

업체 탭은 category filter를 통해 같은 화면에서 다룬다.

### Reservation

예약은 vendor category와 연결되어야 한다.

필수 연결:

- `reservation.id`
- `reservation.vendorId`
- `reservation.status`
- `reservation.kind`
- `reservation.scheduledAt` 또는 희망 일정
- `reservation.nextAction`

확장 연결:

- 관련 checklist task id
- 관련 budget item id
- 방문 질문지 id
- 견적/계약 정보 id

### Budget

새 예산 mock data와 타입을 추가한다.

예시:

```ts
type BudgetPlan = {
  id: string;
  totalAmount: number;
  currency: "KRW";
  categories: BudgetCategory[];
};

type BudgetCategory = {
  id: string;
  label: string;
  plannedAmount: number;
  spentAmount: number;
  note?: string;
  linkedVendorCategory?: VendorCategory;
};
```

### Saved Items

현재 `savedIds`는 좋아요 누른 업체만 의미한다.  
앞으로는 저장된 리포트까지 포함해야 하므로 분리한다.

- `savedVendorIds`
- `savedComparisonReportIds`

업체 탭의 `저장` 섹션에서는 두 데이터를 함께 보여준다.

## 구현 단계

### 1단계: 타입과 상태 정리

- `Screen` 타입 재정의
- `find`를 `vendors`로 변경
- `my`를 `profile`로 변경
- `saved-venues`를 독립 screen에서 업체 탭 내부 상태로 이동
- `budget` screen 추가
- `exploreTab` 대신 `vendorTab` 도입

### 2단계: 하단 탭 변경

- 하단 탭을 `홈 / 로드맵 / 업체 / 예약 / 예산`으로 변경
- AI 탭 제거
- 프로필은 홈 헤더 진입 유지

### 3단계: 업체 탭 재구성

- `FindScreen`을 `VendorsScreen` 또는 `VendorExploreScreen`으로 래핑
- 내부 탭: `추천 / 저장 / 비교`
- 기존 좋아요 목록을 업체 탭 내부로 이동
- 비교 리포트 저장 목록을 같은 저장 탭에 추가할 수 있도록 구조 확보

### 4단계: 예약 탭 강화

- 예약 확정/대기/요청 상태 필터 추가
- vendor category 필터 추가
- 예약 카드에서 category 표시
- 방문 질문지와 캘린더 액션 유지

### 5단계: 예산 탭 추가

- `data/budget.json` 추가
- Budget 타입 추가
- `BudgetScreen` 추가
- 하단 탭 연결
- AI 예산 코치 버튼은 기존 AI sheet로 연결

### 6단계: 홈 재정리

- 홈은 요약과 빠른 진입만 남긴다
- 낮은 중요도 기능은 “이런 서비스는 어때요?” 미니앱 런처로 이동
- 예약 상세 관리는 예약 탭으로 유도
- 업체 탐색은 업체 탭으로 유도

## 구현 시 주의점

- 예약 탭을 탐색 탭 내부로 합치지 않는다.
- AI는 하단 탭보다 context-aware assistant로 쓰는 편이 낫다.
- 업체 탭은 웨딩홀만 하드코딩하지 말고 vendor category를 기준으로 확장 가능하게 만든다.
- 홈의 체크리스트는 로드맵 task와 예약 일정에서 파생되는 요약이어야 한다.
- 예산은 독립 데이터로 시작하되, 나중에 예약/견적/비교 리포트와 연결 가능해야 한다.
- screen 이름 변경 시 localStorage migration 또는 초기화 전략이 필요하다.

## MVP 반영 범위

이번 리팩토링에서 우선 반영할 것:

- 하단 탭 재구성
- 업체 탭 이름/구조 정리
- 예약 탭 유지 및 category 확장 여지 확보
- 예산 탭 추가
- AI 탭 제거 또는 sheet 중심 전환

이번 리팩토링에서 보류할 것:

- 실제 예산 CRUD
- 실제 예약 CRUD
- 실제 캘린더 연동
- 업체 category별 상세 UI 완성
- 실제 AI API 연동
- 비교 리포트 저장/조회 API

## 완료 기준

- 하단 탭이 `홈 / 로드맵 / 업체 / 예약 / 예산`으로 보인다.
- 예약 탭은 독립 탭으로 남아 있다.
- 업체 탭에서 추천 업체와 저장 업체를 볼 수 있다.
- 예산 탭에서 전체 예산과 category별 배분을 볼 수 있다.
- 홈은 요약과 빠른 진입 위주로 단순화되어 있다.
- 기존 체크리스트, 예약, 업체 저장 기능이 깨지지 않는다.
